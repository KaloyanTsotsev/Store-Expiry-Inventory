# Диагностика на products — 21.10.2026

## Установена причина

Предоставеният от потребителя export на `products` (`pbc_4092854851`)
съдържа `@request.auth.role != "admin"` за listRule, viewRule и createRule.
Тези правила изключват admin. PocketBase връща HTTP 200 с празен списък при
неизпълнено listRule и HTTP 400 при неизпълнено createRule.
Това обяснява двата симптома при посочената роля admin.

Източник: https://pocketbase.io/docs/api-rules-and-filters/

Полета от формата: name (непразен text), barcode (text), category (text),
active (bool). Съответстват на предоставената схема. image е optional и не се
изпраща. Няма индекси в export-а. Клиентът изрично изпраща active=true;
export-ът не доказва default=true на сървъра.

## Вариант за първоначално описаната политика: достъп само за admin

След изрично разрешение от собственика, в PocketBase Dashboard → products →
API Rules заменете само трите неравенства с равенства:

```json
{
  "listRule": "@request.auth.role = \"admin\"",
  "viewRule": "@request.auth.role = \"admin\"",
  "createRule": "@request.auth.role = \"admin\""
}
```

Update/Delete остават както са. Не изпразвайте правилата и не отключвайте
колекцията. Не са необходими промени по полета или данни. Това е предложение
за конкретните правила, не файл за импорт на цялата колекция.

## Приложена от потребителя корекция и потвърден резултат

Потребителят съобщи, че е променил правилата на условие „различно от празно“
и е потвърдил показване на продуктите и успешно добавяне на продукт.
Новият точен текст на правилата не е предоставен като export.
Ако условието е `@request.auth.role != ""`, то допуска всяка непразна роля,
а не само admin. Това е различна политика от първоначално заявената.
Агентът не е променял сървърни настройки, схема или данни.

## Наблюдения от реалния сървър

- GET /api/health → 200.
- Анонимен GET /api/collections/products/records с sort=name → 200, два продукта.
  Това съответства на неравенството и потвърждава, че настоящият list endpoint
  допуска анонимен достъп. Няма извършено анонимно създаване на данни.
- GET /api/collections/employees/auth-methods → password е enabled,
  identityFields=[username].
- GET /api/collections/products без токен → 401. Схемата е проверена по
  предоставения export, не чрез привилегирован достъп до сървъра.
- Няма employee credentials/token в работната среда. Не е изпълнен реален
  вход или create като admin. PocketBase Logs и hooks не са инспектирани.
- При по-късна проверка анонимният списък вече връща HTTP 200 с нула записи,
  както през HTTP, така и през реалния Dart SDK getFullList(sort: 'name').
  Впоследствие потребителят потвърди, че е променил правилата.
  Предоставеният export е моментна снимка и може вече да не е актуален.

## Проверка в Android Studio след корекцията на правилата

1. Стартирайте emulator-5554 и приложението от lib/main.dart.
2. Влезте през employees с потребителско име и парола на admin.
3. Отворете Продукти: очаквайте Milk 1L и Yogurt 400g (ако данните са същите).
4. Търсете по име и баркод. Изпробвайте обновяване с жест надолу,
   включително при търсене без резултат.
5. Добавете реален продукт. Проверете, че се появява след връщане и че
   бързо повторно натискане на Запази не създава втори запис.
6. Излезте и потвърдете връщане към Login.
7. Ако create отново върне 400, копирайте HTTP response от екрана/Run console
   и съответния PocketBase Logs запис. Не споделяйте пароли или токени.

Локални проверки: flutter analyze; flutter test; flutter build apk --debug.
`dart run tool/check_products.dart` проверява само анонимно четене през SDK.
Unit тестовете на услугата използват локален тестов HTTP сървър, не PocketBase.
